# a2a-rust 0.14.0: README "Features" claims tested end-to-end

**Subject:** the crates.io releases `a2a-protocol-{sdk,types,client,server} =0.14.0`, which are identical to git `10f3435`.
**Method:** an independent consumer workspace depends only on those crates.io pins and has no path or git dependencies. Every claim runs over real loopback sockets on ports 7500-7999. The SDK server is driven by the SDK client, by raw HTTP (reqwest/curl), or both.
**Date:** 2026-09-26, with `-j 2`. Other workloads shared the host, so no timing here is a performance result.

## FAILED items: minimal repros (each reproduced 3/3 times; see `raw/failed_reruns.txt`)

1. **`A2aRouter` agent card has no HTTP caching.**
   - Repro: `cargo test --test card card_http_caching_per_surface -- --exact --nocapture`
   - Minimal case: serve `A2aRouter::new(handler).into_router()` with a card set, then run `curl -si /.well-known/agent-card.json`.
   - Observed: 200 with no `ETag`, `Last-Modified` or `Cache-Control`, so conditional requests never get 304.
   - Expected, per the README: ETag, Last-Modified and 304, as the JSON-RPC and REST dispatchers provide.
   - Source: `server/src/dispatch/axum_adapter.rs:518-523`.
2. **`RestDispatcher` `/ready` does not probe the task store.**
   - Repro: `cargo test --test stores_hardening health_and_ready_per_surface -- --exact --nocapture`
   - Observed: with the store's `count()` failing, `GET /ready` returns `200 {"status":"ok"}`.
   - Expected: 503, which is what `A2aRouter` returns.
   - Related: `JsonRpcDispatcher` answers `GET /health` and `GET /ready` with **HTTP 200** and a `-32009` JSON-RPC error body.
   - Source: `server/src/dispatch/rest/mod.rs:120-126`.
3. **`PathSegmentTenantResolver` never resolves over HTTP.**
   - Repro: `cargo test --test tenancy path_resolver_over_rest -- --exact --nocapture`
   - Setup: `with_tenant_resolver(PathSegmentTenantResolver::new(1))` plus `TenantAwareInMemoryTaskStore` on a `RestDispatcher`, then `POST /tenants/acme/message:send`.
   - Observed: 400 `request tenant 'acme' does not match the authenticated tenant`.
   - Expected: the request is served under tenant `acme`.
   - Cause: the resolver reads the `":path"` header, which only the WebSocket dispatcher inserts (`tenant_resolver.rs:315-318` vs `dispatch/rest/response.rs:17-25`).
4. **`verify_agent_card` rejects the key format its documentation specifies.**
   - Repro: `cargo test --test signing_isolate -- --nocapture`; `card_signing_roundtrip_over_wire` pins the documented path failing.
   - Steps: sign with `sign_agent_card(card, pkcs8, …)`, then `verify_agent_card(card, sig, spki_der)` using the DER SubjectPublicKeyInfo, as `types/src/signing.rs:450` documents.
   - Observed: `Err("signature verification failed")`, even with no network or serde round trip (`local_verify=false`).
   - Workaround: passing the raw 65-byte SEC1 point verifies.

## Other documentation errors found while following the docs

- `server/src/otel/mod.rs:39` says to pass metrics to `RequestHandlerBuilder::metrics(...)`. The method is `with_metrics`.
- `building-agents/push-notifications.md` never mentions `HttpPushSender::allow_private_urls()`. Without it, any localhost or dev webhook is refused with -32602.
- `client/src/tls.rs:15-16` says to pass a custom rustls config "to the client builder". There is no such method (see #25).
- `types/src/signing.rs:450` says `public_key_der` is DER SubjectPublicKeyInfo. The implementation expects a raw SEC1 point (see FAILED #4).
- `concepts/agent-cards.md` (hot reload) does not explain how to serve `DynamicAgentCardHandler`, or that the built-in dispatchers cannot.
- `book/src/building-agents/stores.md:82` says TTL eviction happens "on access". In fact it happens on write.
- The README's retry row lists 502 and 504 for every call. For sends, only 429 and 503 are retried. The book is correct.
