## 3. Decisions needed

**D-B1 (B-10): keepalive defaults for WebSocket and gRPC.**
- Option A: keep both off, document LB idle timeouts and the two knobs (S, no behaviour change).
- Option B: WebSocket server pings every 30 s by default, independent of the idle-close budget (every conformant client answers; costs a 2-byte frame per 30 s per connection); gRPC server keepalive stays opt-in with docs, because clients may object to PINGs (the dispatcher's own stated reason) and the client deliberately avoids HTTP/2 PINGs (grpc-go GOAWAY).
- Option C: default both on (breaks the maintainers' stated rule that connection knobs default off; risks GOAWAY from strict peers).
- Recommend B for WS plus A for gRPC; keep the client TCP-only.

**D-B2 (B-11): blocking `SendMessage` longer than an LB idle timeout.**
- Option A: document only (use stream or `returnImmediately`, or raise the LB timeout above `send_timeout`).
- Option B: write leading JSON whitespace on a timer; headers must be sent early with status 200, so a later failure can no longer carry an HTTP error status, and it works for neither gRPC nor clients that read status first.
- Option C: lower the client default `send_timeout` below common LB limits (600 s -> 55 s): hides the problem and breaks slow model turns.
- Recommend A, with the book section from B-10(e). B changes error semantics.

**D-B3 (B-25): WebSocket on the HTTP port.**
- Option A: document the limit and point single-port platforms to JSON-RPC/REST/SSE (S).
- Option B: an axum route plus `hyper::upgrade::on` handing the upgraded stream to the existing connection loop (M-L; the loop is written around its own accept path and `WsIo`).
- Option C: add WS upgrade to `CombinedDispatcher` (L; needs a hyper-level upgrade path in the `Dispatcher` trait).
- Recommend A now, B when a single-port platform user asks.

**D-B4 (B-26): forwarded client certificates.**
- Option A: keep the documented limit, add a book recipe for a custom interceptor behind a peer allowlist (S).
- Option B: ship an opt-in `ForwardedClientCertInterceptor` (XFCC, URL-encoded PEM, base64 DER) that requires a trusted-peer CIDR list (M; needs B-09's `trusted_proxies`).
- Option C: do nothing.
- Recommend A now and B after B-09(a); a header-only trust without a peer check is a spoofing hazard.

**D-B5 (B-29): FIPS provider and revocation checking.**
- Option A: declare non-goals, document the `with_tls_config` escape hatches that exist on client, push and JWKS paths, and add `from_oidc_issuer_with_tls_config` (B-04) so every path has one (S).
- Option B: a `fips` feature that makes the `ring_provider()` helpers return `aws-lc-rs` (M; five call sites, a C build dependency, and a feature-unification hazard with the existing `ring` assumptions).
- Option C: add CRL support through `WebPkiServerVerifier` (L).
- Recommend A; revisit B on demand.
