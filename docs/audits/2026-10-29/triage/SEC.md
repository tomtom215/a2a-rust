## 3. Decisions needed

**D-1 (SEC-11): what to do with `BearerTokenTenantResolver::new()`/`Default`.**
- Option A: keep, rely on docs. Cost nothing, but the secret still lands in the DB.
- Option B: `#[deprecated]` on `new()`, drop the `Default` impl. Honest, but removing `Default` breaks callers (pre-1.0, version is 0.16.0).
- Option C: keep both and make them hash the token (SHA-256, hex of the first 16 bytes, prefixed `sha256:`). Fixes secret-at-rest with no compile break; tenant is still caller-chosen, so keep the doc warning.
- Recommendation: C now, plus `#[deprecated(note = "use with_mapper")]` on `new()`, remove in the next minor. `ring` is only an optional dependency of the server (`Cargo.toml:174`), so either make it non-optional for this module or add `sha2`.

**D-2 (SEC-14c): webhook ownership verification.** Options: (1) none, rely on per-host rate cap and `with_allowed_hosts` (non-breaking); (2) challenge handshake before the first delivery (the spec does not define one, so it would be an SDK-only behaviour that real receivers fail); (3) require `with_allowed_hosts` when the card is public. Recommendation: (1), default on, with a conservative per-host cap (for example 5 in flight, 20 requests/s) and a metric when it bites. The handshake is not worth the interoperability cost.

**D-3 (SEC-17): who screens at delivery.** (1) Document only (the book already does). (2) The handler runs `resolve_public_url` before every `send` unless `allows_private_urls()`: wrong for non-HTTP senders (queues) and does not stop a sender's own redirects or second lookup. (3) Ship a public `PublicOnlyResolver` and rustdoc the contract. Recommendation: (3), which is the same code as the SEC-13 fix, so one change covers both.
