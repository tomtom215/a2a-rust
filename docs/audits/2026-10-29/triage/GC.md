## 2. Decisions needed

**D-GC-1 (G-10): `#[non_exhaustive]` on the generated wire structs.** Today a proto field added to `AgentCard`, `AgentSkill`, `AgentInterface`, `AgentProvider`, `Message`, `Task`, `TaskStatus`, `Artifact` or `Part` is a breaking change under STABILITY §2, and STABILITY §4 says the opposite (N-GC-1).
- Option 1: mark all of them `#[non_exhaustive]` in `codegen.toml` for 0.16 and rewrite literals. Closes the gap for good; touches ~100s of literal sites in tests, examples, book (counts by grep: `AgentCard` ~88 lines, `Task` ~153, `Message` ~134), needs builders for `TaskStatus`, `Artifact`, `Part`. L, breaking.
- Option 2: only the four card types (`AgentCard`, `AgentSkill`, `AgentInterface`, `AgentProvider`). They have complete builders, the spec revisions that add fields land mostly there, and examples switch to `AgentCard::new`. M, breaking.
- Option 3: stay exhaustive, and correct STABILITY §4 to say a spec field is a minor-bump break. S, no break, leaves the N16 trap.
- Recommendation: Option 2 now, with `compile_fail` doctests proving a literal no longer builds, and Option 3's wording fix for the remaining types. Deprecate `AgentCard.url` in the same batch.

**D-GC-2 (G-06b): server crate default lacks `tls-rustls`.** A server-only dependency (as installation.md:33 and the server README recommend) cannot deliver https push (fails at delivery, N-GC-5) and has no `Server::with_tls`.
- Option 1: add `tls-rustls` to the server's `default` (matches the client). Breaking per §2; pulls rustls/ring/webpki-roots into server-only builds; opt-out stays.
- Option 2: change the two "Server only" snippets to `features = ["tls-rustls"]` and say why. Docs only, no break, still a trap for readers who skip it.
- Option 3: keep, and make `build()` warn once when push is enabled and the sender cannot do https.
- Recommendation: Option 1. The server's own `ServeConfig::production()` and `with_tls` assume TLS exists, the client already defaults it, and 0.16 is the cheap moment. If the maintainer wants minimal compile defaults, Option 2 plus Option 3.

**D-GC-3 (G-07c): `AgentCapabilities::none()` leaves streaming off.** Spec §3.3.4 requires the server to refuse streaming it did not declare, and the declaration is on the wire, so a default `true` would change every card built with `AgentCard::new`.
- Option 1: default `streaming: Some(true)` in `AgentCard::new`. Fewer refusals; wire-visible change; wrong for agents that do not stream.
- Option 2: keep the honest default; make the rustdoc of `AgentCard::new` and the book's card snippets say "add `.with_streaming(true)` if you stream".
- Recommendation: Option 2 (hello-agent is deliberately non-streaming, book/src/examples/hello-agent.md:173).

**D-GC-4 (G-09): too many ways to serve.**
- Option 1: a `Serve`/listener abstraction so `Server` drives gRPC and WebSocket, plus `A2aRouter::serve(server)`. Right shape, L, breaking if the existing methods are folded in.
- Option 2: normalise only what is cheap and mechanical: gRPC `serve_with_shutdown` to return `ServeReport` (put the io error in `refused`), WebSocket `serve*` to take `self`, and document an "which entry point" table in the book. M, small breaks.
- Option 3: document only.
- Recommendation: Option 3 now, and write the ADR for Option 1 for 0.17. A half-normalised surface two weeks before a release is a worse outcome than an inconsistent one that is documented.

**D-GC-5 (G-13b): a message-id generator, and where the RNG lives.**
- Option 1: optional `uuid` feature on `a2a-protocol-types` giving `MessageId::random()`; enabled by the SDK.
- Option 2: a free function in the client/SDK prelude (`new_message_id()`), leaving types dependency-free (the deliberate rule in message.rs).
- Option 3: client-level `A2aClient::send_text(text)` that mints the id.
- Recommendation: Option 2, because the SDK already carries `uuid` and the types crate's "serde only" property is documented; add `Message::user_text(new_message_id(), "..")` to the README and drop the `uuid` line from first-agent.md. Additive, S.

**D-GC-6 (G-14.2): should `Telemetry::init()` export only where configured?**
- Option 1: change `init()` to `builder().with_export_where_configured().build()`. Quieter in development; behaviour change for anyone relying on localhost export.
- Option 2: keep (it follows the OpenTelemetry environment spec) and say so on `init()`'s rustdoc, pointing to the builder.
- Recommendation: Option 1, since 0.16 is unreleased and `init()` has no caller in the repository. Call it out in the upgrade guide.

**D-GC-7 (G-15): naming sweep.** None of the seven items misbehaves; each rename is a §2 break needing a deprecation window (§3).
- Option 1: do a sweep now (rename `A2aRouter` to say REST; `on_resubscribe` to the spec name; `TenantLimitsBuilder` setters to `with_*`; add `Duration` setters). L.
- Option 2: only additive aliases: `RateLimitConfig::with_window(Duration)`, `RequestHandler::on_subscribe_to_task`, spec-to-SDK name table in book/src/reference/api-reference.md; leave the rest.
- Recommendation: Option 2.

**D-GC-8 (G-18): `RequestContext.context_id` type.**
- Option 1: change field and `RequestContext::new` to `ContextId` (breaking; ripples through user executors that compare it as a string).
- Option 2: keep the `String`, add `RequestContext::context() -> ContextId` and use it internally. No break.
