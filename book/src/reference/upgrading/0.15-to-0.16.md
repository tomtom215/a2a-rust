# Upgrading from 0.15 to 0.16

These come from a pre-release audit (2026-10-29): two defaults that let in
what they should have refused, internal error text reaching callers, and
configuration errors reported as request errors. CHANGELOG.md lists eleven
breaking items under `### Breaking Changes`; each has a section here. The
behaviour changes beside them are in CHANGELOG.md's `### Behaviour Changes`.

Read every section that touches what you use: three of them change what a
running server accepts or answers, and compile silently.

## The WebSocket listener refuses browsers by default

`WebSocketDispatcher` refuses, with `403`, an upgrade whose `Origin` header
it has not been told to allow. An upgrade with no `Origin`, as clients that
are not browsers send (this SDK's included), is accepted as before. A
browser page that connected in 0.15 is refused in 0.16 until its origin is
listed:

```rust
# use std::sync::Arc;
# use a2a_protocol_sdk::prelude::*;
# use a2a_protocol_server::WebSocketDispatcher;
# struct MyAgent;
# agent_executor!(MyAgent, |_ctx, _q| async { Ok(()) });
# fn main() -> Result<(), Box<dyn std::error::Error>> {
# let handler = Arc::new(RequestHandlerBuilder::new(MyAgent).without_agent_card().build()?);
let dispatcher = WebSocketDispatcher::new(handler)
    .with_allowed_origins(["https://app.example.com"]);
# drop(dispatcher);
# Ok(())
# }
```

Origins are compared whole, without regard to ASCII case: scheme, host, and
a port only when it is not the scheme's default. `allow_any_origin()`
restores 0.15's behaviour, and is safe only for a listener that no browser
can reach with credentials worth taking, or that authenticates every call
with something a page cannot send.

## A `JwtValidator` checks `iss` and `aud` by default

A validator that names no issuer refuses every token, and so does one that
names no audience; the interceptor logs why when it is built. In 0.15 both
checks were skipped when unset. Name what you accept:

```rust
use a2a_protocol_server::auth::JwtValidator;

let validator = JwtValidator::new()
    .with_issuer("https://login.example.com/")
    .with_audience("my-agent");
# drop(validator);
```

`allow_any_issuer()` and `allow_any_audience()` opt out, for a key set only
one issuer signs with, such as an HS256 secret you hold. Also changed:

- `from_oidc_issuer` refuses a discovery document whose `issuer` is not the
  one named (a trailing `/` is ignored), and binds that issuer to the
  validator.
- A JWKS or discovery URL must be `https://`, or `http://` to a loopback
  host. With `from_jwks_url`, a plaintext URL makes every token refused,
  with the reason logged.
- `JwtAuthInterceptor::new` is no longer `const`.

## An internal error's text is withheld from callers

An `A2aError` with the internal code, from an executor, a store, an
interceptor or the database, is answered `internal error (reference <12 hex
digits>)`, without its `data`. Its text is logged under that reference
(feature `tracing`). An executor's internal error is withheld from the
task's `Failed` status too. A client, test or dashboard that read the text
from the response reads the reference instead, and finds the text in the
server's log. Errors of other codes and the SDK's own messages are sent as
written. To send the text, as 0.15 did, for a deployment whose errors carry
nothing a caller should not read:

```rust
# use a2a_protocol_sdk::prelude::*;
# struct MyAgent;
# agent_executor!(MyAgent, |_ctx, _q| async { Ok(()) });
# fn main() -> Result<(), Box<dyn std::error::Error>> {
let handler = RequestHandlerBuilder::new(MyAgent)
    .without_agent_card()
    .expose_internal_errors()
    .build()?;
# drop(handler);
# Ok(())
# }
```

## Configuration errors have a variant of their own

Every refusal from `RequestHandlerBuilder::build()` was
`ServerError::InvalidParams`, the variant a refused request carries, and
printed "invalid params: …". It is `ServerError::Config` ("configuration
error: …", metric label `config`). On the client, a zero timeout, an unknown
binding, and gRPC asked for through `ClientBuilder::build()` (it needs the
async `build_grpc()`) were `ClientError::Transport`; they are
`ClientError::Config`, which is not retryable. Code that matched the old variant on a build result matches the
new one:

```rust
use a2a_protocol_client::ClientError;
use a2a_protocol_server::ServerError;

fn misconfigured_server(err: &ServerError) -> bool {
    matches!(err, ServerError::Config(_))
}
fn misconfigured_client(err: &ClientError) -> bool {
    matches!(err, ClientError::Config(_))
}

assert!(misconfigured_server(&ServerError::Config("no agent card".into())));
assert!(misconfigured_client(&ClientError::Config("zero timeout".into())));
```

The client's required-extension check still answers
`Protocol(ExtensionSupportRequired)`.

## `ServeReport` is `#[must_use]`

A server that refused to start returns at once with `refused` set. Code that
dropped the report exited `0` as though it had served; it now gets an
`unused_must_use` warning, an error under `-D warnings`. Read the report:

```rust
use a2a_protocol_server::ServeReport;

fn served(report: &ServeReport) -> Result<(), String> {
    match &report.refused {
        Some(why) => Err(format!("the server did not start: {why}")),
        None => Ok(()),
    }
}
# let _ = served;
```

## TLS configuration types (client)

- `TlsConfig` is `#[non_exhaustive]` and gains `Custom`, which carries an
  `Arc<rustls::ClientConfig>`: extra roots, a pinned certificate, a client
  certificate for mutual TLS. A `match` on it needs a wildcard arm:

  ```rust
  use a2a_protocol_client::config::TlsConfig;

  fn uses_tls(tls: &TlsConfig) -> bool {
      !matches!(tls, TlsConfig::Disabled)
  }
  assert!(!uses_tls(&TlsConfig::Disabled));
  ```

- Because of that `Arc`, `TlsConfig` and `ClientConfig` are no longer
  `UnwindSafe` or `RefUnwindSafe`. Only code that moves one across
  `std::panic::catch_unwind` notices; wrap it in
  `std::panic::AssertUnwindSafe`, as
  [0.14 → 0.15](./0.14-to-0.15/errors-and-rust-api.md#serveserver-is-no-longer-unwindsafe)
  shows for `Server`.
- `ClientConfig::with_tls` and `ClientBuilder::without_tls` are no longer
  `const fn`, and neither is the server's `Server::with_config`. Call them
  outside a `const` context.
- `tls::HttpsClient` is a struct, not a type alias for a hyper client. It
  routes through the proxy the environment names, and the transports use
  its `request` method. Code that named the alias to build its own hyper
  client builds one itself.

## The server's outbound HTTP follows the proxy and CA variables

Push delivery (`HttpPushSender`), JWKS and OIDC discovery
(`JwtAuthInterceptor`) and the tool loop's `OpenAiChatModel` now read
`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY`, and trust the
certificates in `SSL_CERT_FILE` and `SSL_CERT_DIR` beside Mozilla's roots.
Nothing is renamed and nothing fails to compile, but a process that has one of
those variables set for some other tool now sends webhooks, key fetches and
model calls through that proxy. List the hosts that must be reached directly
(an in-cluster identity provider, a model server on the pod network) in
`NO_PROXY`. Idle connections to these hosts are now closed after 50 s instead
of hyper's 90 s, so a receiver behind a 60 s load-balancer timeout is not
sent a request on a connection it has already closed.

**Loopback now bypasses the proxy variables** on every outbound path of the
client and the server (audit NEW-b-2). A process with `HTTP_PROXY` set used to
send a request for `http://127.0.0.1:...` or `http://localhost:...` to the
proxy; it goes direct now, with `NO_PROXY` or not. If a test or a deployment
relied on a loopback destination being proxied (a proxy that fronts a local
service), set `A2A_PROXY_LOOPBACK=1`. `NO_PROXY` entries are read as Go reads
them (`*.example.com` works); an entry with a port is ignored with a warning.

`JwtAuthInterceptor::from_oidc_issuer_with_tls_config` is new: an identity
provider behind a private CA could not be discovered at all before.

Back to [Upgrading Between Minor Versions](../upgrading.md).

## Protocol structs are `#[non_exhaustive]`

Thirteen structs can no longer be written as a struct literal outside
`a2a-protocol-types`: `AgentCard`, `AgentSkill`, `AgentInterface`,
`AgentProvider`, `AgentExtension`, `Message`, `Part`, `Task`, `TaskStatus`,
`Artifact`, `TaskStatusUpdateEvent`, `TaskArtifactUpdateEvent` and
`TaskPushNotificationConfig` (`AgentCapabilities` already was). A field the A2A
specification adds is now a minor-version addition for everyone who builds
them through `new` and the `with_*` setters, where it used to break every
literal. The compiler says `E0639: cannot create non-exhaustive struct using
struct expression` at each one.

Each has a constructor for the fields the protocol requires and a `with_*`
setter for each optional one; a field a setter does not take can still be
assigned, because `#[non_exhaustive]` stops construction and exhaustive
patterns, not field access:

| Was | Is |
|---|---|
| `Task { id, context_id, status, history: Some(h), artifacts: None, metadata: None }` | `Task::new(id, context_id, status).with_history(h)` (also `with_artifacts`, `with_metadata`) |
| `TaskStatus { state, message: Some(m), timestamp: Some(t) }` | `TaskStatus::new(state).with_message(m).at(t)`; `TaskStatus::with_timestamp(state)` still stamps the current time |
| `Message { id, role, parts, task_id: None, … }` | `Message::new(id, role, parts)`, or `Message::user`/`agent`/`user_text`/`agent_text`, with `with_task_id`, `with_context_id`, `with_metadata`, `with_extensions`, `with_reference_task_ids` |
| `Part { content: PartContent::Text(t), metadata: None, filename: None, media_type: None }` | `Part::text(t)`, `Part::raw`, `Part::url`, `Part::data`, with `with_filename`, `with_media_type`, `with_metadata` |
| `Artifact { id, name: Some(n), parts, … }` | `Artifact::new(id, parts).with_name(n)` (also `with_description`, `with_metadata`, `with_extensions`) |
| `TaskStatusUpdateEvent { task_id, context_id, status, metadata: None }` | `TaskStatusUpdateEvent::new(task_id, context_id, status)` and `with_metadata` |
| `TaskArtifactUpdateEvent { task_id, context_id, artifact, append: Some(true), last_chunk: Some(true), metadata: None }` | `TaskArtifactUpdateEvent::new(task_id, context_id, artifact).with_append(true).with_last_chunk(true)` |
| `TaskPushNotificationConfig { task_id: Some(t), url, token: Some(k), … }` | `TaskPushNotificationConfig::new(t, url).with_token(k)` (also `with_id`, `with_tenant`, `with_authentication`); `TaskPushNotificationConfig::for_url(url)` names no task |
| `AgentInterface { url, protocol_binding, protocol_version, tenant }` | `AgentInterface::new(url, binding)` or `jsonrpc`/`rest`/`grpc`, with `with_protocol_version`, `with_tenant` |
| `AgentSkill { id, name, description, tags, … }` | `AgentSkill::new(id, name, description).with_tags(tags)` (also `with_examples`, `with_input_modes`, `with_output_modes`, `with_security_requirements`) |
| `AgentExtension { uri, description, required, params }` | `AgentExtension::new(uri)` with `with_description`, `with_required`, `with_params` |
| `AgentProvider { organization, url }` | `AgentProvider::new(organization, url)` |
| `AgentCard { … }` (fifteen fields) | `AgentCard::new(name, version, interface)` and the `with_*` methods it has had since 0.10; `card.url` and `card.signatures` are assigned or set with `with_signatures` |

Three things to know when converting:

* A literal with `"x".into()` for a `String` field becomes the bare `"x"`: the
  new parameters are `impl Into<_>`, and `.into()` on an argument to one
  cannot be inferred.
* A pattern that names every field (`let Task { id, context_id, status,
  history, artifacts, metadata } = task;`) needs a trailing `..`.
* `Artifact::new` asserts in a debug build that there is at least one part, as
  it did before; `Artifact::unchecked(id, parts)` builds the one a test of
  `Artifact::validate` expects to be refused.

### The other 26 wire structs

The method parameters and responses, the security schemes and flows,
`AuthenticationInfo`, `StringList`, `SecurityRequirement` and
`AgentCardSignature` are `#[non_exhaustive]` too, for the same reason: with the
fourteen above, no struct that the A2A specification can add a field to breaks
its callers when it does. This includes the functional-update form
`Type { field, ..Default::default() }`, which `#[non_exhaustive]` also forbids.
Each has a constructor for the fields the protocol requires and a `with_*`
setter for each optional one. A setter that takes a `String` accepts a `&str`;
one that takes a collection takes the collection.

| Was | Is |
|---|---|
| `SendMessageConfiguration { accepted_output_modes, task_push_notification_config, history_length, return_immediately }` or `..Default::default()` | `SendMessageConfiguration::new()` (the default: plain text accepted) with `with_accepted_output_modes`, `with_task_push_notification_config`, `with_history_length`, `with_return_immediately` |
| `MessageSendParams { tenant, message, configuration, metadata }` | `MessageSendParams::new(message)` with `with_tenant`, `with_configuration`, `with_metadata` |
| `TaskQueryParams { tenant, id, history_length }` | `TaskQueryParams::new(id)` with `with_tenant`, `with_history_length` |
| `TaskIdParams { tenant, id }` | `TaskIdParams::new(id)` with `with_tenant` |
| `CancelTaskParams { tenant, id, metadata }` | `CancelTaskParams::new(id)` with `with_tenant`, `with_metadata` |
| `GetPushConfigParams { tenant, task_id, id }`, `DeletePushConfigParams { … }` | `GetPushConfigParams::new(task_id, id)`, `DeletePushConfigParams::new(task_id, id)`, each with `with_tenant` |
| `ListPushConfigsParams { tenant, task_id, page_size, page_token }` | `ListPushConfigsParams::new(task_id)` with `with_page_size`, `with_page_token`, `with_tenant` |
| `ListTasksParams { tenant, context_id, status, page_size, page_token, history_length, status_timestamp_after, include_artifacts }` | `ListTasksParams::new()` with `with_tenant`, `with_context_id`, `with_status`, `with_page_size`, `with_page_token`, `with_history_length`, `with_status_timestamp_after`, `with_include_artifacts` |
| `GetExtendedAgentCardParams { tenant }` | `GetExtendedAgentCardParams::new()` with `with_tenant` |
| `TaskListResponse { tasks, next_page_token, page_size, total_size }` | `TaskListResponse::new(tasks)` (page and total size are the length) with `with_next_page_token`, `with_page_size`, `with_total_size` |
| `ListPushConfigsResponse { configs, next_page_token }` | `ListPushConfigsResponse::new(configs)` with `with_next_page_token` |
| `AuthenticationInfo { scheme, credentials }` | `AuthenticationInfo::new(scheme)` with `with_credentials` |
| `AgentCardSignature { protected, signature, header }` | `AgentCardSignature::new(protected, signature)` with `with_header` |
| `StringList { list }`, `SecurityRequirement { schemes }` | `StringList::new(list)`, `SecurityRequirement::new(schemes)` |
| `ApiKeySecurityScheme { description, location, name }` | `ApiKeySecurityScheme::new(location, name)` with `with_description` |
| `HttpAuthSecurityScheme { description, scheme, bearer_format }` | `HttpAuthSecurityScheme::new(scheme)` with `with_description`, `with_bearer_format` |
| `OAuth2SecurityScheme { description, flows, oauth2_metadata_url }` | `OAuth2SecurityScheme::new(flows)` with `with_description`, `with_oauth2_metadata_url` |
| `OpenIdConnectSecurityScheme { description, open_id_connect_url }` | `OpenIdConnectSecurityScheme::new(url)` with `with_description` |
| `MutualTlsSecurityScheme { description }` | `MutualTlsSecurityScheme::new()` with `with_description` |
| `AuthorizationCodeFlow { authorization_url, token_url, refresh_url, scopes, pkce_required }` | `AuthorizationCodeFlow::new(authorization_url, token_url)` with `with_refresh_url`, `with_scopes`, `with_pkce_required` |
| `ClientCredentialsFlow { token_url, refresh_url, scopes }`, `PasswordOAuthFlow { … }` | `ClientCredentialsFlow::new(token_url)`, `PasswordOAuthFlow::new(token_url)`, each with `with_refresh_url`, `with_scopes` |
| `ImplicitFlow { authorization_url, refresh_url, scopes }` | `ImplicitFlow::new(authorization_url)` with `with_refresh_url`, `with_scopes` |
| `DeviceCodeFlow { device_authorization_url, token_url, refresh_url, scopes }` | `DeviceCodeFlow::new(device_authorization_url, token_url)` with `with_refresh_url`, `with_scopes` |

A pattern that names every field of one of these needs a trailing `..`, as
above. The protobuf message types under `a2a_protocol_types::proto` (the `pb`
module in the gRPC code) share some of these names and are unchanged.

## `RequestContext.context_id` is a `ContextId`

The field was a `String` beside a `TaskId`. It is now a
[`ContextId`](https://docs.rs/a2a-protocol-types/latest/a2a_protocol_types/task/struct.ContextId.html)
like the one every event and `Task` carries, so an executor passes it on as it
is:

```diff
 let event = TaskStatusUpdateEvent {
-    context_id: ContextId::new(ctx.context_id.clone()),
+    context_id: ctx.context_id.clone(),
     /* … */
 };
```

Where a string is wanted, `ctx.context_id.as_ref()` is the `&str` and
`ctx.context_id.to_string()` the `String`; `Display` and `==` against another
`ContextId` work. A comparison with a `&str` (`ctx.context_id == "x"`) no longer
compiles: compare `ctx.context_id.as_ref()`. `RequestContext::new` takes
`impl Into<ContextId>`, so `"ctx-1"` and `String` still work and a bare
`.into()` of a literal does not infer; drop the `.into()`.

## `AgentCard::new` declares streaming

A card built with `AgentCard::new` now has `capabilities.streaming ==
Some(true)`; in 0.15 it had no capabilities set. Every binding this SDK serves
streams, and a client that honours the card used to refuse to stream against
such a card. The card on the wire gains `"capabilities": {"streaming": true}`,
so its ETag changes. A card that must declare nothing says so:

```diff
 let card = AgentCard::new("a", "1.0.0", AgentInterface::jsonrpc("http://x"))
+    .with_capabilities(AgentCapabilities::none());
```

## `tls-rustls` is on by default in the server crate

`a2a-protocol-server` now enables `tls-rustls` by default, as the client and the
SDK do: its push sender, JWKS and OIDC fetches and the model client reach
`https://` with no feature to add. A project that depended on the server crate
with default features and wants the 0.15 build keeps the old dependency graph
with `default-features = false` and the features it used (`tracing`, `otel`):

```toml
a2a-protocol-server = { version = "0.16", default-features = false, features = ["tracing", "otel"] }
```

## `sign_agent_card` is removed

Deprecated in 0.15.0 for taking an `Option` key id, which let a card signature
leave out the `kid` that spec §8.4.2 requires. Use `sign_card_es256`, whose key
id is a `&str`:

```diff
-let sig = sign_agent_card(&card, pkcs8, Some("my-key"))?;
+let sig = sign_card_es256(&card, pkcs8, "my-key")?;
```

## `Telemetry` installs a subscriber and reads the proxy variables

Two behaviours of `Telemetry` that existing code can notice, prepared as a
0.15.1 that was never published:

- `install_subscriber` now always installs a subscriber, so a
  `tracing_subscriber` `.init()` after it panics. Install yours first, or add
  `Telemetry::layer()` to it.
- `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY` now apply to the
  export. A pod that sets `HTTP_PROXY` for its other traffic and exports to an
  in-cluster collector must list the collector in `NO_PROXY`
  ([Observability](../../deployment/observability/tls-proxies.md#no_proxy-and-an-in-cluster-collector)
  has the entries that match and the ones that do not). Loopback needs no entry:
  it is never sent to a proxy (`A2A_PROXY_LOOPBACK=1` restores that).

## The default bearer-token tenant is a digest, not the token

`BearerTokenTenantResolver::default()` used the raw bearer token as the tenant
id, which put a live credential in every task row, telemetry attribute and
audit record that carries a tenant (audit SEC-11). It now uses
`tenant_id_for_token(token)`: `sha256:` and 32 lowercase hex digits (the first
16 bytes of the token's SHA-256). `BearerTokenTenantResolver::new()` is the
same resolver, deprecated. Neither verifies the token, so neither isolates
tenants; `with_mapper` with a closure that checks the token is still the one for
a deployment.

This compiles and runs, and **changes the tenant of every request** from a
resolver built with `new()` or `default()`: tasks stored under the raw token
are not found under the digest. Either rewrite the tenant of those rows to
`tenant_id_for_token(token)` for each token you hold, or keep the old tenant,
credential in storage included, with
`BearerTokenTenantResolver::with_mapper(|token| Some(token.to_owned()))`. A
resolver built with `with_mapper` is unchanged.

## Every card declares the lineage extension, and a halt can name one job

A server checks a message's lineage (`a2a-rust.com/lineage`, ADR 0034) and
halts by its root, so every agent card now declares
`https://a2a-rust.com/extensions/lineage/v1`, as it already declared the
budget extension. A card you sign before handing it to the builder must
declare it too, or `build()` refuses it, since adding the entry would break the
signature:

```diff
 card.capabilities.extensions = Some(vec![
     AgentExtension::new(IDEMPOTENCY_EXTENSION_URI),
     AgentExtension::new(FAILURE_EXTENSION_URI),
     AgentExtension::new(BUDGET_EXTENSION_URI),
+    AgentExtension::new(LINEAGE_EXTENSION_URI),
 ]);
```

A send whose lineage is malformed or deeper than 16 is now refused as invalid
params before any work; a send without one is unchanged and writes nothing new
on its task.

A halt refusal (`ServerError::Halted`) now carries a `google.rpc.ErrorInfo`
detail with `reason` `HALTED` and `domain` `a2a-rust.com` on every binding.
The code, the HTTP and gRPC statuses and the message are unchanged.

`HaltScope` gains `Root { tenant, root }`. It was already `#[non_exhaustive]`,
so a `match` on it already has a wildcard arm. **With a shared halt store,
upgrade every replica before giving the first root halt:** a 0.15 replica
cannot read that row and stops reading the store, so it hears no later halt or
resume until it is upgraded. A 0.16 replica reads a scope it does not know as
a halt of everything.
