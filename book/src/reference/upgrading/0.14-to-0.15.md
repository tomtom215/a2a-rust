# Upgrading from 0.14 to 0.15

These come from making the SDK follow the A2A 1.0 specification where it did
not, and from moving to current releases of `sqlx`, OpenTelemetry and SLIM.
CHANGELOG.md lists 26 breaking items under `### Breaking Changes` and about a
hundred behaviour changes beside them. Each of the 26 has a section on one of
the pages below; a few need nothing from you but a newer toolchain or an
`AssertUnwindSafe`. The behaviour changes an existing deployment is most likely
to trip over have sections too, and
[Also in 0.15, not breaking](./0.14-to-0.15/not-breaking.md) points to the rest.

The sections are grouped by area. Read every page that touches what you use: a change of behaviour, value or wire format compiles silently.

| Area | What breaks |
|---|---|
| [Toolchain and dependencies](./0.14-to-0.15/toolchain.md) | The MSRV goes to 1.94 for `sqlx` 0.9; OpenTelemetry moves to 0.33; SLIMRPC moves to `agntcy-slim-rpc` 3.4 |
| [Telemetry, dashboards and alerts](./0.14-to-0.15/telemetry.md) | `a2a.server.latency` is removed; `Telemetry` needs the `otlp` feature; `init_otlp_pipeline` takes `Option<&str>`; error labels, histogram buckets, the executor span name and rate-limit keys change |
| [Agent cards and signing](./0.14-to-0.15/agent-cards.md) | `build()` requires a valid agent card and refuses one that carries a credential, has an OAuth URL that is not a URL, or is signed without the budget extension; `sign_agent_card` is deprecated, and a card signed by 0.14 may not verify |
| [Authentication and caller isolation](./0.14-to-0.15/authentication.md) | An authenticator needs a scheme the public card declares, and a card that demands credentials needs an interceptor that checks them; tasks are isolated per caller; caller ids name how the caller authenticated; a JWT with no `sub` and a short HS256 secret are refused |
| [Stores and tenants](./0.14-to-0.15/stores-and-tenants.md) | `save_appending_history` takes a `HistoryLimit`; `TenantLimits::max_stored_tasks` is removed; a request with a tenant needs stores that isolate tenants |
| [Client](./0.14-to-0.15/client.md) | The client refuses responses `a2a.proto` does not allow; `from_card` follows the card's interface order and checks capabilities and required extensions; `CachingCardResolver` honours `max-age`; the REST client sends `application/a2a+json`; `ClientRequest` gains `query_params` |
| [Wire format and bindings](./0.14-to-0.15/wire-and-bindings.md) | HTTP+JSON answers `application/a2a+json`; `TaskState` numbers follow the proto; the gRPC conversion refuses absent REQUIRED fields; only `A2A-Version: 1.0` is served; `pageSize` is 1 to 100; an error's `data` is a ProtoJSON `Any`; a JSON-RPC notification gets no reply |
| [Push notifications](./0.14-to-0.15/push.md) | A push config the server cannot honour is refused at creation and at delivery; push needs a push sender; webhook timeouts are 10 s per request and 30 s per delivery |
| [Streams and executors](./0.14-to-0.15/streams-and-executors.md) | What an executor writes is checked; a parked subscription stays open; a stream that falls behind catches up, and a long replay is read in pages; an appended chunk needs a part; a snapshot cannot move a task back to `Submitted` |
| [Errors and Rust API](./0.14-to-0.15/errors-and-rust-api.md) | Request-field errors are `ServerError::InvalidField`; rate-limit, WebSocket and SLIMRPC error codes change; `ConvertError` and `SseParseError` are `#[non_exhaustive]`; `serve::Server` is not `UnwindSafe`; the conformance kit's cancel check is renamed |
| [Also in 0.15, not breaking](./0.14-to-0.15/not-breaking.md) | Deprecations, replicas sharing a store, `serve` timeouts, header and media-type parsing, path ids on HTTP+JSON, JSON-RPC rules, ListTasks bounds, push-config listing of an unknown task |
